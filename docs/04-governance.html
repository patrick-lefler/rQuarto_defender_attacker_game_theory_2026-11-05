Where Will the Attacker Strike? Assumptions, limits and checks

All money is in $M. Losses are expected loss per targeted ransomware campaign, and the model assumes one campaign per year. All values are illustrative.

How a board should use this

Use this analysis as a challenge to the budget, not as an allocation engine. The numbers are synthetic. What carries over to your own firm is the logic: attackers respond to what we defend, and the best plan is the one that still works when our read of the attacker is wrong.

A board can ask three things. Does our plan state who we think the attacker is? Has anyone tested the plan against a different attacker? What would we change if our threat intelligence were wrong by a third?

Assumptions register

Code 
reg |>
  gt() |>
  cols_label(id = "ID", assumption = "Assumption", why_it_matters = "Why it matters",
             how_it_could_fail = "How it could fail", where_tested = "Where tested") |>
  gt_se() |>
  cols_align(align = "left")

How to read the table. Each row is something we assumed to build the model. The columns say why the assumption matters, how it could turn out wrong, and where this site tests it, if anywhere.

What the table tells you. Several assumptions are not tested here. These are the first places to look when applying the approach to real data, because a wrong assumption can reorder the strategies.

Sensitivity

We changed one assumption at a time and reran the full comparison. The robust strategy was best in 8 of 8 cases, including a lateral-movement case where an identity or corporate IT breach spreads and costs more.

Code 
sens |>
  transmute(assumption, setting,
            best = STRAT_LABELS[best],
            robust_mean,
            next_best = paste0(STRAT_LABELS[next_best], " (", fmt_m(next_mean), ")"),
            robust_p95, textbook_p95) |>
  gt() |>
  cols_label(assumption = "Assumption", setting = "Setting", best = "Best strategy",
             robust_mean = "Robust", next_best = "Next best",
             robust_p95 = "Robust 1-in-20", textbook_p95 = "Textbook 1-in-20") |>
  fmt_currency(columns = c(robust_mean, robust_p95, textbook_p95),
               decimals = 1, pattern = "{x}M") |>
  gt_se() |>
  cols_align(align = "left", columns = c(assumption, setting, best, next_best))

How to read the table. Each row changes one assumption and reruns every strategy. Values are expected loss in $M when we misjudge the crew; the last two columns are the 1-in-20 bad case.

What the table tells you. The ranking does not depend on these settings. Larger misjudgment raises every loss but robust still leads, and the textbook plan’s bad case stays far above robust’s.

Limitations

The model has no repeated play: one campaign, one decision. It has no deception or honeypots, which can change what the crew sees. It has one attacker type, so insiders and state actors are out of scope. Assets fail independently: a breach of identity or corporate IT does not spread to other systems, although real ransomware crews often move laterally. The sensitivity table tests a simple version of this. The budget is static, so it does not respond to new intelligence during the year.

Natural follow-ons are repeated play, mixtures of attacker types, and the attack-graph Markov chain project.

How to read the table. Each row is a test of the calculations. “Pass” means the check met its standard. The detail column states what was checked.

What the table tells you. The checks cover the solver, the robust optimizer, the budget, and the Monte Carlo draws.
